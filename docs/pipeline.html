From headline to authority record

TTE, NLB's Thesaurus and Taxonomy Editor, holds about 1.8 million records. 52,437 of them name the people, organisations, places, events, awards, programmes and laws that the news reports on, each with a description a cataloguer wrote. Keeping them current with the news is routine work that the volume has outgrown. This reads the news twice a day, and has read the archive back to 2015 once, and proposes the changes; a person decides every one. Traced below through one real article. The funnel

Each stage is cheap enough to run on everything reaching it, because the stage before threw most of the work away. The expensive judgement happens last and least often.

Two funnels share one design. The archive is the outlets' own archives from January 2015 (The Straits Times, Lianhe Zaobao, CNA), run once through an internal model. The live pipeline has read the feeds twice a day since 3 August 2026.

Cards come in article order, the article's subject first. An entity the article only mentions, or one whose record is already up to date, is not a card. The article's side states what changes and which source said it; the record's side is shown as it is. An award or organisation named is marked in TTE or not in TTE yet, since it must be a record before it can go on one. A card is checked out to one reviewer when it is dealt and stays theirs until they stamp it, so no record is ever worked twice; each stamp is saved as it is made.

The pipeline's copy of the authority file is read-only and always will be. Each new TTE dump replaces it, record by record, so anything written back would be overwritten; the change has to be made in TTE, where it belongs, and arrives with the next dump.

What each prompt is made of

Nothing above is a single file. The task instructions and the cataloguing rules are separate, and assembled at call time, so extraction and resolution cannot drift apart about what a field means or what belongs in it. The rules themselves are compiled from NLB's own cataloguing guidelines and the Occupations Thesaurus. The three jobs are stages 1, 2 and 4 above; stage 3 is SQL and needs no prompt.

Job 1 · Relevance 460 tokens
relevance.txt460 the whole prompt, nothing injected
Job 2 · Extraction 2,476 tokens
extraction.txt1,780 the task: which entities, which facts, the evidence rule
+ tte/fields_brief.txt 703 at {field_rules}: the allowed fields per entity type, under TTE's exact names

resolution.txt2,442 the task: identity first, then the merge strategies

+ tte/description_style.txt 589 at {description_style}: how to write one, and separately how to edit one that already exists
+ tte/notability.txt 262 at {notability}: whether an entity warrants a record at all
Deliberately not sent 9,863 tokens withheld
− tte/occupations.txt 973 277 terms from the Occupations Thesaurus. Checked in code instead, so Chairperson cannot get through as an occupation whatever the model returns.
− tte/vocabularies.txt 579 six controlled lists (Nationality, Title, Feature Type and others), checked the same way
− tte/field_rules.txt 8,311 all 113 field definitions, compiled from the guidelines as a reference for people, not for the model

The last block is the load-bearing one. A longer prompt is not a better one: injecting all 34,000 characters of cataloguing guidance made the model skim it, use short field names anyway, and find one entity in an article where it had previously found five. Code rejects a bad value more reliably than a prompt asks for a good one, so the closed lists are enforced after the answer comes back and never spent on instructions.

What the brief actually looks like, in the prompt:

ALLOWED FIELDS, by entity type. Omit any you have no value for.

PERSON        Name · Title · Description · Occupation · Nationality ·
              Place of Birth · Birth Year (yyyy) · Birth Month (mm) ·
              Birth Day (dd) · Death Year (yyyy) · ... ·
              Awards · Affiliations(groupName) · Spouse · Child · Parent
ORGANISATION  Name · Description · Country · Street Address · Postal Code ·
              Founder · Year Started (yyyy) · ... · Group Members · Awards

The suffixes are the point. TTE stores Birth Year (yyyy) and Affiliations(groupName), with no space before the bracket in the second. A value filed under Birth Year or Affiliations (groupName) creates a new field rather than extending the one that exists, which is silent and worthless. Every hand-written field list this replaced got some of them wrong.

What it never does

Never edits the catalogue. Not one proposal has changed a record. Every path out ends at a person.
Never invents a record id. A match must name a record the database offered; anything else is discarded before it is stored.
Never invents a field. Field names are corrected against TTE's schema in code, and occupations against the official thesaurus.
Never marks work done before it is. Each queue is a column written only after the result is stored, so a crash leaves the work queued.

Where it can still go wrong

270,690 Articles set aside on one unreviewed judgement each, permanently out of the queue: 90.6% of everything collected (3,362 live, 267,328 archive). If the first filter is even slightly wrong, everything downstream enriches the wrong remainder and nothing would ever say so. Where a second model disputed a rejection, a person found the filter right 62 times in 69; the rest have never been read.
0 / 170 Cards decided on the online desk so far; the field test starts in October. In the first trial round, on the offline desk, identity was confirmed 14 of 14, one by search after the model romanised a Chinese name wrongly, and 13 of 16 field changes were accepted. Everything else about output quality is inference.
3,057 Entities the model believes are in TTE under another name, and names it: “DBS Foundation” for 星展银行基金会, “Health City Novena” for 诺维娜健康城. Nothing searches again with that name yet.
15,494 Relevant archive articles that have not been through extraction: 12,447 of 27,941 have.
1 to 4 Entities the same article yields on repeated extraction runs. Comparing two versions of that prompt needs many runs of each, and no such test exists.
6 / 22 Description rewrites that would delete more than 30% of the existing text. One cut a 636-character description to 405, dropping a Navy career and ten years as Deputy Prime Minister. The review screen now warns before showing the wording.

The pipeline runs at midnight and noon Singapore time, one step after another: any new TTE dump uploaded is loaded first, then relevance, extraction and resolution, then the desk's cards are published.

The field rules and vocabularies are compiled from the NLB cataloguing guidelines (KOS Guidelines for Name Construction in TTE, v5.1) and the Occupations Scope Notes thesaurus. This page is for NLB readers.
